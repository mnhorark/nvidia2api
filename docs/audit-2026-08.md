## 一、阻断级（Blocker）

### B1. Docker 构建注定失败 ✅已修复：前端未配置静态导出，镜像却引用 `/fe/out`

* **位置**：`Dockerfile`（`COPY --from=fe /fe/out /app/static/frontend`）、`frontend/next.config.mjs`、`backend/config/urls.py`

* **问题**：`next.config.mjs` 未设置 `output: 'export'`，`next build` 永不产出 `out/` 目录；且 Django 路由没有任何前端静态文件托管（仅 `api.urls`），即便复制成功也无法提供服务。

* **复现**：`docker compose build` → BuildKit 报 `/fe/out: not found`。

* **影响**：README 宣称的 `docker compose up -d` 主部署路径完全不可用。

* **修复**：

  1. `next.config.mjs` 增加 `output: 'export'`；
  2. 新增 `backend/api/frontend_views.py` 负责静态托管（静态资源精确匹配 + 前端路由 `index.html` 回退 + 目录穿越防护），`api/urls.py` 增加负向前瞻 catch-all `^(?!api/|v1/|c/|healthz|metrics)`，确保未知 API 路径不会被 SPA 外壳吞掉；docker-compose 中移除独立的 frontend 服务，改为单一 all-in-one 镜像；
  3. CI 增加 `pytest` / `next build`（含 `out/` 产物断言）/ `docker build` 三步骤。

* **验证**：用**真实构建产物**把链路跑通 —— `next build` 产出 13 个预渲染路由 + 26 个 `_next` 资源文件，将 `FRONTEND_DIR` 指向 `frontend/out` 后经 Django test client 实测：`/`、`/dashboard`、`/login` 均 200，`/proxies/edit/42` 正确回退到 SPA 外壳，`/_next/static/*.js` 带 `immutable` 长缓存而 HTML 为 `no-cache`，`/api/admin/does-not-exist`、`/v1/nope`、`/../backend/config/settings.py`、`/_next/static/nope.js` 均 404。

* **修复过程中连带发现的两个缺口**（均已修）：

  * `_resolve()` 原先先 `lstrip("/")` 再判穿越，导致 `/etc/passwd` 被当成导出目录内的**相对路径**处理，绝对路径检查形同虚设。已改为在 `lstrip` 之前判定，并同时检查原文与 `unquote` 后的形式（覆盖前置代理原样转发 `..%2F` 的情况）。

  * CI 无 `.env`，凭据会落回 `admin123`/`dev-admin-token`，而 H3 的安全门禁在非 DEBUG 下拒绝默认凭据启动——会连带把 `pytest` 整个打挂（`settings` 导入期即抛 `RuntimeError`）。已在 CI 的 backend job 显式设置 `ALLOW_DEFAULT_CREDENTIALS=true`，并已用"默认凭据 + 放行"本地模拟 CI 环境复跑全量套件确认通过。

## 二、高危（High）

### H1. 渠道熔断器"一次性失效"：冷却过期后永远无法再次熔断 ✅已实证 ✅已修复

* **位置**：`backend/services/channel_health.py:70`

* **问题**：熔断写入条件为 `cooldown_until__isnull=True`。首次熔断后该字段永久非空，冷却过期后若上游仍故障，`consecutive_failures` 超过阈值也**无法再次进入冷却**，且每次失败都误打 "tripped circuit breaker" 日志。

* **实证**：5 次系统级失败触发熔断 → 手动将冷却置为过去 → 再失败 1 次 → `re-trip: False`，`cooldown_until` 停留在过去。

* **影响**：上游整体故障时所有请求持续打满 N 条竞速线路，空耗并发与上游配额——熔断机制名存实亡。

* **修复**：条件改为 `Q(cooldown_until__isnull=True) | Q(cooldown_until__lte=now)`；日志仅在冷却实际写入时输出。

* **回归测试**：`H1_CircuitBreakerRetripTests.test_breaker_retrips_after_cooldown_expires`（**已转正为常规守卫**）

### H2. 三个对外协议端点对"非对象 JSON"请求体直接 500 ✅已实证 ✅已修复

* **位置**：`backend/api/openai_views.py:174`（`_run_authed` 直接 `body.get(...)`）

* **实证**：POST `/v1/chat/completions` body 分别为 `[1,2,3]` / `"str"` / `123` → 全部 500（`AttributeError`）。`/v1/responses`、`/v1/messages` 同样命中。

* **影响**：合法/非法客户端的畸形请求产生 500 噪音；可用性信号被污染。

* **修复**：`_parse_body` 后统一校验 `isinstance(body, dict)`，否则 400 `invalid_request_error`。

* **回归测试**：`H2_NonDictJsonBodyTests`（5 条，**已转正为常规守卫**）

### H3. 默认管理凭据即生产凭据 ✅已修复

* **位置**：`backend/config/settings.py:122-124`、`.env.example`

* **问题**：`admin/admin123` + 静态 `ADMIN_TOKEN=dev-admin-token` 为出厂值，仅启动告警不阻断；Token 永不过期、不可轮换；泄露后 `?reveal=1` 可明文回读全部上游 Key。

* **影响**：公网部署 + 默认凭据 = 管理面完全失守。

* **修复**：`DEBUG=false` 时检测到默认值即拒绝启动；支持 Token 多值/轮换；文档强化首次部署改密指引。

## R2-High（实证确认）

### R2-H1. 单个渠道 Key 创建接口必然 500 ✅已修复

* **位置**：`api/admin_views.py:376`（`ChannelKeyListView.post`）

* **问题**：调用了不存在的 `key_service._key_stored_in_channel`（重构 `bulk_import_keys` 去重逻辑时的遗留调用）。

* **实证**：`POST /api/admin/keys {"api_key": "sk-x"}` → `AttributeError` → 500；带空 key 的请求（匿名线路）正常。

* **影响**：控制台上"添加单个 Key"功能完全不可用（批量导入不受影响，故测试套件没覆盖到）。

* **修复**：在 `key_service` 补 `_key_stored_in_channel(channel, key)`（解密比对去重）。

### R2-H2. Responses/Anthropic 流式出口丢失 tool\_calls 续包参数 ✅已修复

* **位置**：`services/responses_api.py:892-912`、`services/anthropic_api.py:409-448`

* **问题**：OpenAI 标准流式协议中 `tool_calls[].id` **只在首包出现**，续包只有 `index + arguments`；
  两个出口都只按 `id` 匹配/累积参数——续包被静默丢弃（responses 侧）或生成 `id=""/name=""` 的幽灵工具块（anthropic 侧）。

* **实证**：模拟 OpenAI 标准续包序列 → responses 最终 `arguments=''`；anthropic 产生 2 个 `content_block_start`（第二个 id/name 全空，参数全进了幽灵块）。

* **影响**：走 OpenAI 官方行为上游的 `/v1/responses`、`/v1/messages` 流式工具调用参数全丢/错乱，Claude Code 类客户端直接不可用。

* **修复**：按 `tc["index"]` 维护 index→tool 关联表，续包无 id 时回查映射。

### R2-H3. Responses 上游时终结事件重复发送 ✅已修复

* **位置**：`services/responses_api.py:915-956`（`iter_chat_sse_as_responses`）、`anthropic_api.py:451-463`

* **问题**：`_translate_event` 对 `response.output_text.done`（带 usage）与 `response.completed` 各产出一个 `finish_reason` 非空的 chunk；两个包装器对**每个** finish chunk 都发一轮 `output_item.done` + `response.completed` / `message_delta` + `message_stop`，无 `done_sent` 防护。

* **实证**：双 finish chunk 序列 → `response.completed` 出现 2 次。

* **影响**：严格 SDK（openai-python ResponseStream、anthropic-sdk）在终结事件后再收事件会抛错/误判流损坏。

* **修复**：首次 finish 后立即收尾 return；补 `done_sent` 防护。

### R2-H4. 登录接口在 Token 轮换期签出无效 Token ✅已修复

* **位置**：`api/admin_views.py:170`（`LoginView.post` 返回 `settings.ADMIN_TOKEN`）

* **问题**：`ADMIN_TOKEN="tokA,tokB"`（轮换多值）时签发的是**整串原文**，而鉴权按单值匹配 → 登录成功但后续请求全部 401，控制台陷入"登录成功→被登出"死循环。

* **实证**：override 多值配置 → 登录返回 `tokA,tokB` 原串，带它请求 → 401。

* **修复**：签发 `auth.py` 的 `valid_admin_tokens()[0]`（首个有效 Token）。

### R4-H1. 单 worker + 事件循环同步 DB 写 → SQLite 写锁风暴冻结全站 ✅已修复

* **位置**：`Dockerfile`（`CMD ... uvicorn ...`，单进程单 worker）、

## R5-High（实证确认）

### R5-H1. 胜出后"首内容超时"复用 90s 首字节超时 → 慢思考模型被误杀 ✅已修复

* **位置**：`api/openai_views.py:_stream_response`（`first_content_timeout = float(
  sysconfig.get("stream_first_byte_timeout")...)`）、`api/admin_views.py` 同、
  `services/sysconfig.py`（LEGACY 映射 `first_content_timeout -> stream_first_byte_timeout`）。

* **机制**：宽松判胜只锁定"谁先开始出流"（首个结构 chunk，可能是空 delta/role 块）。
  但胜出后转发阶段又用 **90s（stream\_first\_byte\_timeout 默认）** 强掐"首个真实内容"：
  慢思考模型（kimi/R1 类）连接后先回 role 块、随后静默思考 1\~5 分钟才吐首个
  reasoning —— 90s 一到即抛 `first_content_timeout` → 未交付正文 → 换线重试；
  用户已关闭重试 → **直接失败**。与用户"竞速成功几十秒、首字几百秒 / 失败"
  的体验完全吻合。

* **负优化本质**：`stream_first_byte_timeout` 语义被混用（竞速阶段首字节超时 +
  胜出后首内容超时），且**与宽松判胜自相矛盾**——宽松判胜说"不等内容"，
  90s 强掐却说"必须 90s 内出内容"。

* **参考校准**：new-api 流式透传 `RELAY_TIMEOUT` 默认 0（不限时，保活用 HTTP/2
  PING）；cliproxy 无延迟透传、不掐流。本项目 SSE `: keep-alive` 心跳已承担
  客户端侧保活，无需应用层强掐慢思考。

* **修复**：

  1. 新增独立参数 `stream_first_content_timeout`（默认 **0 = 不限制**），
     胜出后默认完全透传；仅当用户确认线路"先响应后永久卡死"时才调小；
  2. `_stream_response` / `AdminChatView` 改从新参数读取；
  3. LEGACY 映射修正：旧 `first_content_timeout`（语义就是"胜出后等待首个正文"）
     改映射到 `stream_first_content_timeout`，此前误映射到竞速阶段的首字节超时。

* **回归测试**：`R5_StreamJudgementTests`（宽松判胜保留 / 裸 \[DONE] 防呆 /
  新参数默认 0 / LEGACY 映射正确）

1. **竞速明细应展示上游原始原因**：分类（`http_400`）只说明"上游拒绝"，
