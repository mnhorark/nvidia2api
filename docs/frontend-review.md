## 二、前端架构分析

### 2.1 分层与组织

```
app/(console)/  路由组（10 个管理页 + layout 侧边栏/渠道切换器）
app/login/      登录
components/     设计系统（ui.tsx：Button/Card/Modal/DataTable/Toggle/Badge/Select/Input...）
                + toaster + channel-switcher
lib/            api.ts（请求封装/类型集中）+ use-local-storage + use-submit-guard
```

- 页面组件全部 `"use client"`，静态导出（`output: 'export'`）由 Django 同源托管 ✅

- 设计系统组件集中在 `components/ui.tsx`（约 230 行），风格统一 ✅

- 业务类型全部集中在 `lib/api.ts`（30+ 接口类型），前后端契约单一来源 ✅

### 2.2 状态管理

- 无全局 store（Redux/Zustand 均未引入）——个人项目合理，组件内 useState + 路由组
  `key={channel}` 重挂载实现渠道作用域刷新

- 持久化偏好：`useLocalStorage`（模型筛选/时间范围/自动刷新等，带解析兜底）

- 防重：`useSubmitGuard`（提交在途禁用）；请求竞态：各页 `seqRef` 递增丢弃过期响应

- 渠道作用域：`lib/api.ts` 统一注入 `X-Channel` 头 + 全局 channel-change 事件 ✅

### 2.3 路由设计

- App Router 路由组 `(console)` + 独立 `/login`；`error.tsx` 错误边界；
  SPA fallback 由后端 `frontend_views` 负向前瞻托管（API 路径不被吞）✅

### 2.4 数据获取

- 页面级 `useEffect` + `Promise.all` 并行拉取；dashboard 追加 10s 轻量轮询（只刷 stats 不重拉用量图）✅

- 超时/401 跳转/错误归一统一在 `lib/api.ts` ✅

## 三、WebUI 整体架构理念

1. **零重型依赖**：无 UI 框架（纯 Tailwind + 自绘 SVG 图表）、无图表库、无全局 store —— 构建产物小、加载快
2. **设计令牌驱动**：全部样式走 CSS 变量 + Tailwind 语义色，改主题成本低
3. **前后端契约集中**：`lib/api.ts` 单文件承载全部请求封装与类型
4. **交互安全兜底**：防重、竞态、空值兜底、错误重试、reduced-motion —— 经历多轮审查打磨

## 五、优化方案（含仪表盘重点）

### 5.1 改进目标

1. **仪表盘加载与容错体验**：首载骨架屏消除数字闪跳；加载失败可一键重试（已实施）
2. **模型管理正确性**：同步并清理能清理"上游已下线但已启用"的模型；新增"仅清理不同步"（已实施）
3. **图表交互增强**（后续可选）：hover 焦点高亮、数值标签
4. **分布 drill-down**（后续可选）：Top6 + "查看全部"

### 5.3 技术选型建议

- **图表**：维持自绘 SVG（零依赖）。若后续需要折线/面积趋势图，可选轻量 `recharts`
  （\~90KB，React 原生，比 ECharts 轻一个量级）——**仅在确需时才引入**

- **状态管理**：维持无全局 store；页面量超过 15 或出现跨页共享复杂状态时再评估
  `zustand`（\~1KB）

- **样式**：维持 Tailwind + 令牌；不引入 CSS-in-JS

### 5.4 预期效果评估

- **仪表盘**：首载骨架屏消除"数字从 — 跳到值"的跳动感；失败可重试，避免刷新页重来

- **模型管理**："同步并清理"真正可用（能清启用模型）；"仅清理不同步"不打扰上游、
  快速整理本地列表

- **回归保障**：R8 守卫锁死清理口径，防再次退化
